# 雲端版圖表選型與資料契約

本批為三張圖表，不另套報告版型。沿用使用者已接受的深藍介面；使用者先前明確拒絕淺灰底，因此深底優先於模板的預設紙色。SVG 字型使用本機 Inter 與繁體中文 fallback，不下載字型。

## 候選檢視

先檢視 L1–L20，再檢視 F1–F17。與本體不符的網路、占比、階層、問卷、OHLC、五數概括、事件生命史均不選用。主力候選比較如下：

| 圖 | 候選 | 判斷 |
|---|---|---|
| 降雨輸入 | L3 Barcode Lollipop | 能表達一筆一時點，但區間平均雨強必須保留開始與結束；圓點標記較易被誤讀成瞬時觀測 |
| 降雨輸入 | F2 Hairline Line | 逐點折線會暗示區間間線性變化，且與結果時序重複輪廓 |
| 降雨輸入 | **F3 Hairline Area** | 保留每個輸入區間一根從零開始的發絲線及峰值標記。頂邊改成按原始區間保持常數的階梯，以免創造不存在的雨型 |
| 當時 >10 cm 面積 | L3 Barcode Lollipop | 421 個儲存時點會過密，重複峰值標記不能幫助讀取退水 |
| 當時 >10 cm 面積 | F3 Hairline Area | 面積填充的骨架適合，但與雨量圖重複且容易把「面積隨時間」誤看成累積面積 |
| 當時 >10 cm 面積 | **F2 Hairline Line** | 日曆底線、單一細線與逐筆點保留真實輸出時點；曲線可下降，直接說明當時面積 |
| 水量收支 | L14 Hundred Field | 把量四捨五入成百分點會遮掩帳面殘差；不採用 |
| 水量收支 | F7 Stacked Rungs | 可以呈現去向，但無法把「逐項扣除」和最後實際留水的差異講清楚 |
| 水量收支 | **F9 Rung Waterfall** | 梯狀總量、虛線扣除、虛線層級接續保留；最後留水直接取求解器輸出，殘差另明寫，不湊成零 |

不使用 Glance、後備圖或新造圖型。三張圖型不重複。

## 鎖定模板

| 編號 | 卡內原標題 | 核心保留 |

| F3 | Concurrent users, filled with days | 一筆一直線、基準零線、頂邊輪廓、峰值點及標數 |
| F2 | Thirty days of sign-ups | 時間底線刻度、細折線、逐筆實點、峰值標記 |

## 統一色板

沿用已接受介面作 custom 角色：底 `#081f5c`、卡 `#142f60`、文字／峰值 `#edeff1`、輔助文字 `#bdcde5`、網格 `#647ea9`、資料 `#9ebfe9`。顏色只分資料、唯一峰值與環境結構；強度仍由縱向位置表示，不靠色相猜大小。所有圖共用一套角色，不加入新色相。

## 資料契約

- 降雨：呼叫 backend.forcing 的真實輸入，以信義區報告格各雨站占比作面積加權。縱軸 mm/h；總雨量按每段精確秒數積分，不能用雨強相加。延長退水段只畫明示無雨假設。
- 面積：只讀取 `native/history.csv` 的 `time_s`、`xinyi_area_gt10_km2`。此為當時面積，不能換成整段曾超過的面積或淹水機率。
- 收支：全計算域。總進水包含初始儲水；入滲、外框流出、原生排出逐項扣除；有未回地表溢流時獨立列出。最後留水是實際地表加原生儲水。顯示未經隱藏補平的殘差。
- SVG 像素座標按真值線性映射、從零起算；不斷軸、不做峰值平滑。所有時間點仍可滑桿或指標查詢。
- 來源字串只經完整 HTML／JSON 跳脫，SVG 資料文字用 `textContent`。缺值、NaN、Infinity 與不合法負值直接拒絕。

## 整合

`rainfall_html(req)` 回傳 `(html, total_mm, metadata)`；`history_html(folder)` 與 `budget_html(summary)` 回傳 HTML。以 Streamlit `components.html` 內嵌，手機卡片高度必須經實際瀏覽器量測後設定，建議先保留 560–600 px 或啟用 iframe 滾動避免截掉來源。數字明細表仍可保留，圖不取代原生驗證證據。
